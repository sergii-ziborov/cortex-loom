# Cortex LLM backends

`cortex_prepare` returns a deterministic evidence packet, a coverage
certificate, and `changePlan`. The plan lists source and test targets that
survived the packet budget, with exact paths, line ranges, and citation IDs.
`ready_for_upstream_review` means the coverage certificate is sufficient and
at least one source target is present. It does not claim an edit was made.

`workflowStep.active: false` still means the agent profile only recommended a
Cortex sequence; it did not execute the Superpowers-inspired script.

| `CORTEX_LLM_BACKEND` | Coding change behavior |
| --- | --- |
| `off` (default) | Deterministic evidence and change plan; no model call |
| `local` | Source-anchored Qwen coding preview when coverage and risk allow it |
| `composer` | Source-anchored Haiku, Sonnet, Opus, or Composer preview through a loopback proxy |

`CORTEX_LLM=1` with no backend flag still means `local`.
`CORTEX_LLM_BACKEND=off` wins over that legacy flag. The existing
`internalModel` field describes the routing classifier only. On a coding
change, the lexical route is already `upstream_strong`, so the classifier is
skipped. Check `codingDraft.called`, `codingDraft.status`, and
`codingDraft.totalTokens` to see whether the advisory model actually ran.
Count its tokens in full-task comparisons; `usageKind: unknown` is not zero.

## Advisory coding preview

For a medium-risk code change with complete source coverage, the selected
model may suggest up to three exact replacements. Each `find` must occur once
in the cited excerpt sent to the model and once in the live repository file.
Unknown citations, non-unique anchors, and missing paths discard the affected
suggestion. `discardedSuggestions` and `discardReason` disclose that loss;
the whole draft falls back when no valid suggestion remains. Stale snapshots,
invalid schema, and conflicting or overlapping valid edits reject the whole
draft. Identical repeated edits are collapsed after each citation and source
match is checked. The accepted status is
`accepted_for_upstream_review`: the upstream coding agent still evaluates the
replacement, edits the code, and runs tests. No change is applied by Cortex.
The returned `summary` is generated by Cortex from the accepted edit count;
it does not repeat a model claim that the whole task was completed.
High-risk or insufficiently evidenced work stays upstream with the
deterministic packet. Weavatrix Refactor keeps its preview and confirmation
boundary.

The model reuses the configured classifier endpoint as transport for this
separate advisory call. Its classification calibration does **not** establish
coding quality. An accepted source anchor does not establish semantic
correctness; compare full coding-task quality and tokens before claiming a
saving. A failed or rejected draft falls back to `changePlan` and the source
packet, with a reason in `codingDraft.reason`.

## Model setup

The checked-in `config/llm-profiles.json` points to an operator's Qwen OVMS
deployment. An OpenAI-compatible local runtime uses `/v3`. A local profile
with runtime `ollama` uses the native loopback `/api/chat` endpoint for coding
drafts and `/v1` compatibility for classification. Cortex
does not silently substitute models or connect to remote model hosts.

For Codex MCP, put backend settings under `[mcp_servers.cortex-loom.env]`
in `~/.codex/config.toml` (see [installation](install.md#codex)). A shell
environment assignment on `codex exec` is not proof that its MCP child
received it. In a coding task, check `codingDraft.called: true` and a
reported `codingDraft.totalTokens` before labeling a run “local Qwen” or
“Composer.” Use a fresh `CORTEX_LOOM_DB` per benchmark lane so packets and
memory do not cross the comparison boundary.

For Composer, configure a loopback OpenAI-compatible proxy:

```sh
CORTEX_LLM_BACKEND=composer
CORTEX_COMPOSER_BASE_URL=http://127.0.0.1:8787
CORTEX_CLASSIFIER_MODEL=sonnet-5
CORTEX_COMPOSER_API_KEY= # or CURSOR_API_KEY
```

The aliases are `composer`, `sonnet-5`, `opus-5`, and `haiku`.
`classifierModel` selects the classifier for one prepare; `draftModel`
selects the coding preview. The draft defaults to `classifierModel`, then the
operator's configured Composer model. A per-call alias cannot override an
off or local backend. The CLI accepts `--classifier-model` and
`--draft-model`; MCP accepts `cortex_prepare({ repository, task,
draftModel: "haiku" })`.

Coding agents should request `responseFormat: "plain"`. It returns the same
metadata as JSON followed by exact, unescaped `context.content` source text.
`json` remains the default for programmatic clients.

## Example fields

```json
{
  "changePlan": {
    "status": "ready_for_upstream_review",
    "sourceTargets": [{"path": "src/store.rs", "startLine": 31, "endLine": 106, "evidenceId": "ev_..."}],
    "testTargets": [],
    "reviewRequired": true
  },
  "internalModel": {"role": "routing_classifier", "called": false, "skipReason": "lexical_floor_upstream_strong"},
  "codingDraft": {
    "role": "coding_draft",
    "mode": "local",
    "status": "accepted_for_upstream_review",
    "called": true,
    "accepted": true,
    "mutationAuthority": false,
    "usageKind": "provider_reported",
    "totalTokens": 850,
    "edits": [{"evidenceId": "ev_...", "find": "old exact code", "replace": "new code", "rationale": "review this change"}]
  }
}
```

The example omits fields and uses placeholder values.
